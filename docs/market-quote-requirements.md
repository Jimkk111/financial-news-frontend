# 行情中心（个股/指数详情页 + 新闻联动）需求分析

> 目的：为「行情图表 + 新闻×行情联动」功能提供完整的需求定义、接口契约草案与迭代范围划分，作为前后端开发的共同依据。
> 状态：草案 v1（待评审） · 2026-10-06
> 关联文档：`docs/backend-integration-requirements.md`（后端契约总纲）

---

## 一、背景与目标

### 1.1 背景

项目当前定位为财经新闻平台，具备新闻浏览、创作、AI 助手等能力，但**没有任何金融领域数据**：用户读到一条「某公司发布利好」的新闻后，无法回答"这只股票今天/当时到底涨了多少"。行情是财经资讯场景的刚性配套，也是本项目区别于通用新闻项目的核心差异化点。

### 1.2 产品目标

1. 用户可以搜索并查看个股/指数的**分时图与 K 线图**，获得基础行情阅读体验。
2. **新闻与行情双向联动**：
   - 在 K 线/分时图上看到"这一天发生过什么新闻"；
   - 在新闻详情页看到关联标的及其实时涨跌，并可一键跳转行情页。
3. 为后续 WebSocket 实时推送（快讯、价格跳动）预留数据与接口基础。

### 1.3 技术目标（工程价值）

1. Canvas/SVG 大数据量图表渲染：K 线缩放、平移、手势交互保持流畅。
2. 建立"结构化行情数据"的后端采集-落库-缓存链路，沉淀一套与内容系统解耦的行情领域模型。
3. 打通内容系统与行情系统：新闻-标的多对多关联模型，支持人工与自动两种建联方式。

### 1.4 非目标（本期明确不做）

| 不做 | 原因 |
|------|------|
| 模拟交易/组合管理 | 超出资讯平台边界，合规风险 |
| WebSocket 实时推送 | 独立功能规划，本期限轮询，接口设计预留升级 |
| 港股/美股/期货/基金 | 本期仅 A 股股票与指数，缩小标的库范围 |
| 复杂技术指标全集（MACD/KDJ/BOLL 等） | 本期仅 MA 均线 + 成交量，指标框架预留扩展位 |
| 期货/外汇分钟级高频数据 | 免费源质量差，价值低 |

## 二、术语表

| 术语 | 定义 |
|------|------|
| 标的（symbol） | 一只股票或一个指数，统一标识如 `600519.SH`（贵州茅台）、`000001.SH`（上证指数） |
| 分时图 | 当日按 1 分钟采样的价格走势（240 个点），叠加均价线与昨收基准线 |
| K 线（蜡烛图） | 以日/周/月为周期的开高低收（OHLC）+ 成交量图形 |
| 均线（MA） | N 日收盘价移动平均，本期 MA5 / MA10 / MA20 / MA60 |
| 复权 | 对除权除息日的历史价格进行调整；本期支持「前复权 / 不复权」切换 |
| 停牌 | 标的暂停交易，期间无分时与成交数据 |
| 红涨绿跌 | A 股配色惯例：上涨为红色、下跌为绿色（与欧美相反，需固定遵循） |

## 三、用户与场景（用户故事)

目标用户：关注财经资讯的普通读者/个人投资者，无专业交易需求。

| # | 用户故事 | 验收关注点 |
|---|---------|-----------|
| U1 | 作为读者，我想搜索股票名称或代码，进入它的行情页，看看最新价格和走势 | 搜索联想 ≤ 300ms 反馈；代码/名称/拼音均可命中 |
| U2 | 作为读者，我想看当日分时图和近期日 K，切换周期与均线，判断走势 | 周期切换 < 500ms；手势缩放平移流畅 |
| U3 | 作为读者，看到 K 线上一根大阳线，我想知道"那天发生了什么新闻"，点开标记直接读 | 标记准确落在交易日；点击展示当日新闻列表 |
| U4 | 作为读者，读新闻时看到"相关标的"卡片（名称+涨跌幅），我想点进去看行情 | 卡片实时涨跌；跳转不丢失来源页 |
| U5 | 作为作者，我发布一条新闻时，想把它关联到 1~N 只相关股票，让读者能从行情页找到这篇新闻 | 编辑器内搜索选择；保存后双向可达 |

## 四、功能需求

优先级定义：**P0** = MVP 必须，缺则功能不成立；**P1** = 第二迭代；**P2** = 锦上添花。

### F1 标的搜索与发现（P0）

| 编号 | 需求 | 说明 |
|------|------|------|
| F1.1 | 标的搜索联想 | 输入代码（`600519`）/ 名称（`茅台`）/ 拼音首字母（`gzmt`）均命中；前端 300ms 防抖；下拉支持键盘 ↑↓ 选择、Enter 确认、Esc 关闭 |
| F1.2 | 热门标的 | 行情页默认展示热门标的列表（如沪深300 成分股成交额 Top 20 + 主要指数），后端可配置 |
| F1.3 | 空结果态 | 无命中时展示"未找到相关标的"并保留输入 |
| F1.4 | 搜索入口 | 行情页顶部搜索框（P0）；全局 Header 搜索支持直接输入股票代码直达（P1） |

### F2 个股/指数详情页（P0）

页面路由：`/market/:symbol`（如 `/market/600519.SH`），需登录态之外可访问（游客可见，与新闻详情一致）。

#### F2.1 页头报价区

展示：名称、代码、交易所、**最新价（大号字）**、涨跌额、涨跌幅（%）、今开 / 昨收 / 最高 / 最低 / 成交量 / 成交额；个股额外展示换手率，指数不展示。

- 涨跌配色遵循红涨绿跌；平盘为灰色。
- 涨跌幅精确到小数点后 2 位；价格根据标的展示对应精度（A 股 2 位）。

#### F2.2 分时图（P0）

- 上半区：价格折线 + 均价线（黄色）+ 昨收水平基准虚线；左轴为价格、右轴为相对昨收的涨跌幅 %，双轴对称。
- 下半区：每分钟成交量柱状图，红绿按该分钟价格相对前分钟涨跌着色。
- 交易日 9:30–11:30、13:00–15:00 共 240 分钟为满轴；未开盘时段轴自动收拢到已有数据宽度。

#### F2.3 K 线图（P0）

- 主图：蜡烛图（阳线红色空心/实心、阴线绿色，跟随全局配色）+ MA5/MA10/MA20/MA60 折线。
- 副图：成交量柱。
- 默认加载最近 120 根日 K；最多可加载至全部可得历史（约 250 根/年）。
- 交互：滚轮/双指捏合缩放（改变可视根数），拖拽平移查看历史；移动端单指拖动即平移。

#### F2.4 周期与复权切换（P1）

- 周期 Tab：分时 / 日 K / 周 K / 月 K；周 K、月 K 由后端聚合或前端聚合（见接口草案，推荐后端聚合）。
- 复权切换：不复权 / 前复权，切换后重拉数据，当前可视区间尽量保持（记住中心日期）。

#### F2.5 十字光标与 Tooltip（P0）

- 按住/悬停出现十字线，吸附到最近数据点；Tooltip 展示：日期时间、开/高/低/收、涨跌幅、成交量/成交额、各均线值。
- 移动端触摸拖动时 Tooltip 固定在图区顶部避免遮挡手指。
- 松手/移出后十字线消失，回到最新价定位。

#### F2.6 数据刷新（P1）

- 交易时段内页面可见时，分时图与页头报价每 15~30s 轮询刷新（`document.visibilityState` 控制：不可见暂停、恢复可见立即刷一次）。
- K 线历史不轮询，仅在周期/复权切换时拉取。
- 响应中携带 `serverTime`，前端不做本地时间推断。

#### F2.7 交易状态展示

- 停牌：图区遮罩提示「该标的已停牌」，分时区显示最近交易日数据并标注日期。
- 非交易时段（收盘/周末/节假日）：正常展示最近交易日数据，页头标注「收盘」与数据日期。
- 新股上市不足 60 日：缺失的 MA 线直接不画，不报错。

### F3 新闻 × 行情联动（P0，核心亮点）

#### F3.1 行情图上的新闻标记（P0）

- **日/周/月 K**：有新闻的交易日，在该根 K 线正上方绘制新闻标记点（报纸 icon），一天多条新闻时叠加数字角标。
- **分时图**：当日新闻按其 `publishTime` 定位到对应分钟，在价格线上方打标记。
- 标记与蜡烛不重叠遮挡；缩放平移时标记跟随其数据点。
- 点击标记 → 打开**当日新闻抽屉**（右侧抽屉/移动端底部抽屉），列出该交易日关联新闻：标题、来源、发布时间、一句话摘要；点击条目跳转新闻详情（新路由，返回保留行情页状态与图表可视区间）。

#### F3.2 新闻详情页的关联标的模块（P0）

- 新闻详情页正文头部下方展示「相关标的」卡片条：每只标的显示名称、代码、**最新价与实时涨跌幅**（进入页面时拉取一次快照，不做轮询）。
- 卡片点击跳转 `/market/:symbol`。
- 无关联标的不展示该模块（不留空位）。

#### F3.3 关联关系的建立方式（需求核心）

新闻与标的是**多对多**关系，关联数据带 `source`（建立方式）与 `status`（生效状态）。三条路径：

| 方案 | 机制 | 优先级 | 说明 |
|------|------|--------|------|
| A. 编辑手动关联 | 编辑器新增「关联标的」选择器：搜索联想选择 1~5 只标的，随草稿保存 | **P0** | 保证 MVP 数据质量；实现成本最低，复用 F1 搜索接口 |
| B. 规则自动提取 | 维护「公司名/简称/曾用名/别名 → 代码」词典，对标题+摘要做分词匹配 | P1 | 存量回填的主力；误报通过人工确认流兜底 |
| C. AI 实体抽取 | 复用后端 AI 能力，从正文抽取公司实体并映射代码，输出置信度 | P1 | 爬虫管线入库时自动执行；低于阈值的进「候选关联」待确认 |

- 自动关联（B/C）产生的记录初始 `status = pending`，人工（或阈值自动）批准后 `approved` 才在前端展示；`confidence` 字段记录置信度。
- **存量新闻回填**（P1）：跑批脚本对历史新闻执行 B/C 提取，产出候选关联，逐批确认生效。
- 删除/下架新闻时需同步清理关联记录（见边界场景 E8）。

#### F3.4 联动数据接口

行情页标记点请求当前可视区间的新闻（见 `GET /symbols/:symbol/news`）；新闻详情页通过 `GET /news/:id` 新增的 `relatedSymbols` 字段渲染卡片。契约见第五节。

### F4 行情数据链路（后端，P0）

#### F4.1 数据源选型

| 候选 | 能力 | 优点 | 风险 | 结论 |
|------|------|------|------|------|
| 东方财富 push2/push2his | 实时快照、K 线、分时（trends2） | JSON 格式友好、字段全、支持复权参数 | 非官方接口，字段可能变更 | **主源** |
| 腾讯 qt.gtimg.cn / ifzq.gtimg.cn | 快照、K 线（含前复权） | 稳定、历史久 | GBK 编码需转码 | **备源** |
| 新浪 hq.sinajs.cn | 快照 | — | 2021 起需伪造 Referer，频控严 | 仅兜底 |
| akshare（Python 库） | 多源聚合封装 | 免维护适配层 | 引入 Python 栈，与后端技术栈耦合 | 后端为 Python 时可复用 |

> 具体接口 URL 与参数以实施时抓包验证为准；**所有免费源均为非官方接口，须设计备源切换与降级**，且本项目数据仅用于学习演示，不得对外商用或二次分发。

#### F4.2 标的库与代码适配

- 后端维护标的库表（见 F6）：统一存 `code + exchange`（如 `600519` + `SH`），对外统一输出 `symbol = "600519.SH"`。
- 各数据源的代码格式（新浪/腾讯的 `sh600519`、东财的 `secid = 1.600519`）由**后端适配层转换**，前端永远只见统一格式。
- 标的库初始化：从东财/交易所公开列表一次性导入 A 股全部股票与主要指数，每日增量同步（新股上市、名称变更、退市）。

#### F4.3 采集与缓存策略

| 数据 | 策略 |
|------|------|
| 实时快照 quote | 交易时段按需拉取 + Redis 缓存 TTL 5~15s；收盘后缓存最后快照并打「收盘」标记 |
| 分时 timeline | 交易时段按需回源当日增量；每日收盘后将当日全量固化落库 |
| 日/周/月 K | 收盘后定时批量补齐活跃标的；冷门标的按详情页请求触发回源补齐 |
| 停牌/退市 | 标的库状态标记，不再回源 |

- 回源失败自动切换备源；双源失败返回缓存旧数据 + `stale: true` 标记（前端展示「数据延迟」）。
- 请求频率自我限制（令牌桶），避免触发源站风控。

#### F4.4 与现有爬虫模块的关系

现有 `POST /crawler/crawl` 是 AI 指令驱动的新闻抓取（一次性会话式），行情采集是**结构化定时管道**，两者复用「出站请求管理（UA/Referer/频率/代理）」能力，但不共用入口；建议后端抽独立的 `quote-collector` 模块。

### F5 接口契约草案（前端视角）

> 以下为前端期望契约，字段名遵循现有 camelCase 约定；后端实现时如调整，需同步更新本文档。

```
GET /symbols/search?q={keyword}&limit=10
→ Symbol[]                         // 代码/名称/拼音首字母匹配

GET /symbols/hot
→ Symbol[]

GET /quotes/:symbol                // 实时快照
→ QuoteSnapshot

GET /quotes/:symbol/timeline       // 当日分时（含均价），收盘后返回固化数据
→ TimelineData

GET /quotes/:symbol/kline?period=day|week|month&fq=none|qfq&limit=120
→ KlineData                        // 建议后端聚合周/月K

GET /symbols/:symbol/news?from={YYYY-MM-DD}&to={YYYY-MM-DD}&page=1&pageSize=20
→ PaginatedResponse<NewsItem>      // K 线标记点按需拉取可视区间新闻

GET /news/:id
→ NewsDetail（新增字段 relatedSymbols: SymbolQuote[]）
```

TypeScript 类型草案（落地到 `src/types/market.ts`）：

```ts
export type SymbolType = 'stock' | 'index'
export type Exchange = 'SH' | 'SZ'

export interface Symbol {
  symbol: string        // "600519.SH"
  code: string          // "600519"
  exchange: Exchange
  name: string          // "贵州茅台"
  pinyin: string        // "gzmt"
  type: SymbolType
  status: 'listed' | 'suspended' | 'delisted'
}

export interface QuoteSnapshot {
  symbol: string
  name: string
  price: number
  change: number          // 涨跌额
  changePercent: number   // 涨跌幅 %
  open: number
  preClose: number
  high: number
  low: number
  volume: number          // 手
  amount: number          // 元
  turnoverRate?: number   // 换手率 %，指数无
  tradeDate: string       // 数据所属交易日 "2026-10-06"
  serverTime: string      // ISO 时间戳
  stale?: boolean         // true = 数据源异常，返回的是过期缓存
}

export interface TimelinePoint {
  time: string        // "HH:mm"
  price: number
  avgPrice: number    // 均价（黄色线）
  volume: number
}

export interface TimelineData {
  symbol: string
  preClose: number
  points: TimelinePoint[]
  newsMarks?: { time: string; count: number }[]   // P1：当日新闻标记
}

export interface KlineBar {
  date: string          // "2026-10-06"
  open: number
  high: number
  low: number
  close: number
  volume: number
  amount: number
  newsCount?: number    // 该交易日关联新闻数（联动标记，P0 由独立接口或本字段二选一）
}

export interface KlineData {
  symbol: string
  period: 'day' | 'week' | 'month'
  fq: 'none' | 'qfq'
  bars: KlineBar[]
}
```

> 联动标记数据获取方式二选一（开发前确认）：① K 线接口直接内联 `newsCount`/`newsMarks`（一次请求，推荐）；② 前端拿到 bars 后再调 `/symbols/:symbol/news?from&to` 汇总（两次请求，接口解耦）。推荐 ①，避免可视区间平移时的请求风暴。

### F6 数据模型草案（后端）

```
symbol            标的库：id, code, exchange, name, pinyin, type, status, listed_date, updated_at
quote_snapshot    实时快照：Redis Hash，key = quote:{symbol}，TTL 15s（收盘固化）
kline_bar         K 线：symbol_id, period, fq_type, trade_date, open, high, low, close, volume, amount
                  唯一键 (symbol_id, period, fq_type, trade_date)
timeline_point    分时：symbol_id, trade_date, time, price, avg_price, volume（按 trade_date 分区/归档）
news_symbol       新闻-标的多对多：news_id, symbol_id, source(manual|rule|ai), confidence, status(pending|approved), created_by, created_at
                  唯一键 (news_id, symbol_id)
```

索引：`kline_bar(symbol_id, period, trade_date)`；`news_symbol(symbol_id, status)`（行情页按标的反查新闻）；`news_symbol(news_id)`。

## 五、交互与视觉要求

1. **配色**：红涨绿跌为默认且与暗色模式两套色板对齐；涨跌色同时用于文字、蜡烛、成交量柱（保持一致性）。是否提供「绿涨红跌」设置项 → 见待确认问题 Q2。
2. **加载态**：图表区骨架屏（与 `NewsListSkeleton` 风格一致）；页头报价数字先出、图表后出（分阶段渲染）。
3. **错误/空态**：行情源失败显示旧数据 + 「数据延迟」角标；无分时数据（停牌）显示明确文案；所有失败提供重试按钮。
4. **响应式**：桌面端图表区与新闻抽屉左右分栏；移动端全屏图表 + 底部抽屉，手势优先（延续现有 BottomNav 移动端体验）。
5. **图表主题**：亮/暗两套图表配色随主题切换即时生效，不闪白。

## 六、非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 行情页 LCP ≤ 2.5s（懒加载图表库，图表库独立 chunk，如 `vendor-klinecharts`）；120 根 K 线拖拽/缩放保持 60fps（低端移动设备 ≥ 45fps） |
| 数据量 | 分时 240 点/日；K 线单次 ≤ 500 根（接口分页 limit 上限） |
| 兼容性 | 与现有浏览器支持范围一致（现代浏览器 ES Module）；移动端 iOS Safari / Android Chrome 手势可用 |
| 降级 | 任一数据源故障不影响页面框架渲染；新闻联动数据缺失不打断行情图展示 |
| 合规 | 免费源数据仅用于学习演示；页面标注「数据仅供参考，不构成投资建议」 |
| 安全 | 行情接口公开只读；搜索接口限流防刷 |

## 七、边界与异常场景清单

| # | 场景 | 预期行为 |
|---|------|---------|
| E1 | 停牌标的 | 页头显示最后价格 + 「停牌」徽标；分时区遮罩提示；K 线正常但缺口期无 bar |
| E2 | 退市标的 | 可搜索到但标记「已退市」，仅展示历史 K 线，无快照 |
| E3 | 新股上市 < 60 日 | MA60 缺线不报错；上市首日无昨收，涨跌幅显示 `--` |
| E4 | 除权除息日 | 不复权视图当日出现跳空（正确行为）；前复权视图平滑 |
| E5 | 周末/节假日 | 展示上一交易日数据，页头标注数据日期；分时轴为最近交易日 |
| E6 | 长假后首日 | 分时昨收基准 = 节前最后收盘价 |
| E7 | 指数标的 | 无换手率字段，页头隐藏对应项 |
| E8 | 新闻被删除/下架 | 同步删除 news_symbol 关联；行情页标记数与实际可打开新闻数一致 |
| E9 | 新闻关联标的被退市 | 卡片仍展示但标灰「已退市」，可点击查看历史 K 线 |
| E10 | 数据源被封/字段变更 | 自动切备源；双源失败返回 `stale` 缓存；告警日志 |
| E11 | 一天同一标的 5 条新闻 | 标记聚合成一个点 + 角标数字，抽屉内完整列表 |
| E12 | 新闻发布时间在非交易日（周末发文周一关联） | 按 publishTime 所在自然日匹配；非交易日的新闻归入下一交易日? → 归入发布自然日，若该日无 bar 则标记挂在最近一根后续 bar 上（见 Q4） |
| E13 | 时区 | 后端统一北京时间（Asia/Shanghai）存储与返回，前端不做时区换算 |
| E14 | GBK 编码源（腾讯） | 后端转码，契约层永远 UTF-8 |

## 八、迭代范围与里程碑

| 里程碑 | 范围 | 预估 |
|--------|------|------|
| **M1 — 行情基础**（P0） | 标的库导入 + 搜索/热门；行情详情页：页头快照 + 分时图 + 日 K + 十字光标/手势；后端采集链路（东财主源 + 腾讯备源 + Redis 缓存）；图表库选型 spike | 1.5~2 周 |
| **M2 — 新闻联动**（P0/P1） | 编辑器「关联标的」选择器；news_symbol 表 + 相关接口；K 线新闻标记 + 当日新闻抽屉；新闻详情相关标的卡片；周期切换 + 复权；交易时段轮询 | 1~1.5 周 |
| **M3 — 自动化与体验**（P1/P2） | 规则词典自动提取 + 存量新闻回填；AI 抽取管线接入爬虫；迷你 sparkline（新闻卡片内嵌走势缩略图）；全局搜索直达标的；五日分时 | 1~1.5 周 |
| **M4 — 实时化**（独立规划） | WebSocket 快讯推送 + 价格跳动，替换轮询（与本需求接口兼容，平滑升级） | 另立需求文档 |

> 图表库选型建议在 M1 第一天做 spike 验证：候选 **klinecharts 9**（K 线专用、内置蜡烛/副图/手势/十字光标，定制成本低）vs **ECharts 5 candlestick**（生态成熟、分时/迷你图一并解决，但 K 线手势与大数据量需自己补）。倾向：K 线用 klinecharts，分时与 sparkline 用 ECharts，或全部 klinecharts——以 spike 结果定，选型结论回填本文档 Q1。

## 九、风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 免费源不稳定/被风控 | 高 | 双源热备 + Redis 缓存 + stale 降级 + 自我限频；绝不前端直连源站 |
| 新闻-标的关联质量差（自动提取误报） | 中 | P0 仅人工关联保证质量；自动关联走 pending→approved 审核流 + 置信度阈值 |
| 图表性能不达标 | 中 | M1 首日 spike 压测 500 根缩放；Canvas 方案兜底；图表库懒加载 |
| K 线接口与联动标记请求放大 | 低 | 联动数据内联 K 线响应（F5 推荐方案①）；前端按可视区间节流请求 |
| 与 WebSocket/AI 后续规划冲突 | 低 | quote 接口已带 serverTime 与快照语义，未来切 WS 推送仅替换传输层 |
